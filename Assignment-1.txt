AWS EC2, S3 and IAM Assignment

Launch and Configure an EC2 Instance

First, I logged in to the AWS Management Console and opened the EC2 service.

From the EC2 dashboard, I clicked on Launch Instance to create a new virtual machine. I gave the instance the name Assignment-EC2 so that I could easily identify it later.

For the operating system, I selected Amazon Linux. I chose the t3.micro instance type because it is suitable for a basic assignment and does not require a powerful configuration.

Next, I created a key pair. This key pair can be used to securely connect to the EC2 instance if I need to access it later.

I also created a security group for the instance. Since I only needed SSH access, I allowed traffic through port 22. Instead of allowing SSH access from anywhere, I selected My IP so that only my current IP address could access the instance. This is safer than allowing access from everyone.

For storage, I configured an 8 GB gp3 EBS volume and enabled encryption to protect the data stored on it.

After checking all the settings, I launched the EC2 instance. I waited for the instance to start and verified that its status changed to Running.

Finally, I checked the instance details to make sure everything was working properly and took a screenshot for the assignment.

Create an S3 Bucket with a Lifecycle Policy

For the second part, I opened the S3 service from the AWS Management Console.

I clicked on Create Bucket and entered a unique name for the bucket. I selected the AWS Region required for the assignment.

Since the bucket did not need to be publicly accessible, I kept Block all public access enabled. This helps prevent the files stored in the bucket from being accidentally exposed to the internet.

I also enabled Bucket Versioning so that older versions of files can be kept if an object is modified or replaced. This can be useful if I need to recover an earlier version of a file.

For data protection, I enabled Server-Side Encryption using SSE-S3. This ensures that the objects stored in the bucket are encrypted.

After checking the settings, I created the S3 bucket.

Once the bucket was created, I opened it and went to the Management section. From there, I selected the option to create a Lifecycle Rule.

I named the lifecycle rule ArchiveOldFiles and configured it to apply to all objects in the bucket.

I then configured the lifecycle rule with the following settings:

After 30 days, objects are moved to S3 Standard-IA.
After 90 days, objects are moved to S3 Glacier.
After 365 days, objects are automatically deleted.

The main purpose of this lifecycle rule is to automatically move older files to cheaper storage classes and eventually delete them when they are no longer required. This helps reduce storage costs and also means that I do not have to manage old files manually.

After configuring all the settings, I saved the lifecycle rule and checked that it was active.

Finally, I verified the bucket and lifecycle configuration and took screenshots as proof that the configuration was completed.
